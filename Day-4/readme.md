# Day 4: Cryptography for Humans (Encoding, Encryption & HTTPS)

## 🔐 Fundamentals of Cryptography
Cryptography transforms information to ensure **Confidentiality** (secrets stay secret), **Integrity** (data remains unchanged), and **Authenticity** (verifying origin).

---

## 🔁 Encoding vs. Encryption vs. Hashing
Understanding the technical distinctions between data transformation methods:

| Feature | Encoding | Encryption | Hashing |
| :--- | :--- | :--- | :--- |
| **Purpose** | Data format conversion | Confidentiality & privacy | Data integrity & fingerprinting |
| **Key Required?** | ❌ No | ✅ Yes (Secret Key) | ❌ No |
| **Reversible?** | ✅ Yes (Anyone can decode) | ✅ Yes (Only key holder) | ❌ No (One-way mathematical function) |
| **Examples** | Base64, Hex, URL Encoding | AES-256, RSA | SHA-256, Argon2 |

> ⚠️ **Key Security Rule:** Base64 is NOT security. Obfuscating API keys or passwords in Base64 offers zero protection since anyone can decode it instantly.

## 🔑 Symmetric vs. Asymmetric Encryption

### 1. Symmetric Encryption
* **Mechanism:** Uses a single shared key to encrypt and decrypt data.
* **Characteristics:** Extremely fast; ideal for bulk data (disks, active stream traffic).
* **Primary Standard:** AES-256 (Advanced Encryption Standard).
* **Challenge:** Securely distributing the key between parties without interception.

### 2. Asymmetric Encryption (Public-Key Cryptography)
* **Mechanism:** Uses a mathematically linked key pair:
  * **Public Key:** Shared publicly; used to **encrypt** data or **verify** signatures.
  * **Private Key:** Kept secret on device; used to **decrypt** data or **create** signatures.
* **Primary Standards:** RSA, ECC (Elliptic Curve Cryptography).
* **Analogy:** Anyone can drop a letter into your locked mailbox (Public Key), but only you hold the key to open it (Private Key).

## 🌐 How HTTPS & Certificates Work
HTTPS secures web communication by wrapping HTTP inside **TLS (Transport Layer Security)**.

### The HTTPS Handshake
1. **Client Hello:** Browser connects to server (e.g., `bank.com`).
2. **Certificate Exchange:** Server presents its SSL/TLS certificate containing its Public Key.
3. **Verification:** Browser verifies the certificate against trusted **Certificate Authorities (CAs)** like Let's Encrypt or DigiCert.
4. **Key Exchange:** Both parties compute a shared symmetric session key using **Diffie-Hellman**.
5. **Encrypted Session:** All subesquent HTTP traffic is encrypted using fast symmetric AES.

> 🔒 **The Padlock Fallacy:** The browser padlock means the connection is **private**, NOT that the website is **honest**. Phishing sites also use HTTPS certificates.

## 🛡️ Digital Signatures & Data Integrity

### Digital Signatures
* Generated by hashing data and encrypting that hash with the sender's **Private Key**.
* Anyone can verify authenticity using the sender's **Public Key**.
* Proves non-repudiation and guarantees the code/document has not been altered since signing.

### Hashes for Integrity
* **Avalanche Effect:** Changing a single bit in the input completely alters the output hash.
* Used to verify software downloads (e.g., matching SHA-256 checksums) and analyze malware on platforms like VirusTotal.
