# Day 7: Linux for Security (Terminal, Permissions, Users & Logs)

## 🐧 Why Linux for Security?
Linux powers over 90% of cloud infrastructure, web servers, routers, and dedicated security operating systems (e.g., Kali Linux, Ubuntu, Parrot OS). Mastering the Linux CLI is essential for SOC analysts, penetration testers, and incident responders to perform rapid analysis over SSH without a graphical interface.

---

## 📁 Linux File System Hierarchy
In Linux, everything is treated as a file or directory stemming from the root directory (`/`).

* `/` – Root directory (the top of the file tree).
* `/root` – Home directory for the root superuser.
* `/home` – Personal directories for unprivileged users.
* `/etc` – System configuration files (e.g., `/etc/passwd`, `/etc/sudoers`, `/etc/ssh/sshd_config`).
* `/var/log` – System and service logs (critical for forensic analysis).
* `/bin` & `/usr/bin` – Essential user binaries and commands.
* `/tmp` – Temporary storage (world-writable; frequently targeted by malware for payload staging).
* `/proc` & `/dev` – Kernel interfaces, process information, and hardware devices.

## 🛠️ Essential Terminal Commands

| Command | Purpose | Security Context / Example |
| :--- | :--- | :--- |
| `pwd` | Print working directory | Identifies your current directory path. |
| `ls -la` | List all files including hidden | Reveals hidden configuration files (e.g., `.bashrc`, `.ssh`). |
| `cd` | Change directory | Navigate through the filesystem. |
| `cat` / `less` | View file contents | Inspect configuration files or script source code. |
| `cp` / `mv` / `rm` | Copy / Move / Remove | Manage files (`rm` permanently deletes without a trash bin). |
| `mkdir` | Create directory | Structure workspace or staging folders. |
| `find` | Locate files by attributes | `find / -type f -name "*.conf"` locates configuration files. |
| `grep` | Search text patterns | `grep -i 'failed password' /var/log/auth.log` extracts SSH brute-force attempts. |

## 👤 Users, Privilege Management & SUID

### Users & Groups
* **Account Files:** `/etc/passwd` stores user account details; `/etc/shadow` stores encrypted password hashes (accessible only by root).
* **Least Privilege:** Web applications and background services should run under low-privilege accounts (e.g., `www-data`), limiting attacker impact during a breach.

### `sudo` & Access Control
* Allows authorized users to execute specific commands with root privileges via `/etc/sudoers`.
* Every `sudo` invocation is logged to `/var/log/auth.log` to maintain accountability.

### File Permissions
Permissions are divided into **Owner**, **Group**, and **Others** with numerical values: **Read (4)**, **Write (2)**, **Execute (1)**.

* `600` (`-rw-------`): Private key or secret file (Owner read/write only).
* `644` (`-rw-r--r--`): Standard data file (Owner write; all read).
* `755` (`-rwxr-xr-x`): Standard executable script or binary.
* `777` (`-rwxrwxrwx`): Fully open permission (**Critical Security Risk**).

### SUID Bit & Privilege Escalation
* **SUID (Set Owner User ID):** Runs a file with the permission of the file owner (usually root), regardless of who executes it.
* **Audit Command:** `find / -perm -4000 2>/dev/null`
* Misconfigured SUID binaries (documented on [GTFOBins](https://gtfobins.github.io/)) allow attackers to elevate privileges to root (e.g., executing shell calls through `find` or `vim`).

## 🔄 Processes, Services & Persistence

### Process Monitoring
* `ps aux`: View a static snapshot of all active processes.
* `top` / `htop`: Real-time interactive resource monitor (identify CPU spikes from unauthorized processes/crypto-miners).
* `kill -9 <PID>`: Terminate a specific process by Process ID.

### Services & Persistence Vectors
* **Systemd (`systemctl`):** Manage background services (`systemctl status <service>`).
* **Cron Jobs (`crontab`):** Scheduled tasks executed automatically. Attackers often insert malicious scripts into `/etc/cron.*` or user crontabs to maintain persistence across reboots.

---

## 🔍 Log Analysis & Networking Diagnostic Tools

### Key Log Files (`/var/log/`)
* `auth.log` / `secure`: Authentication attempts, SSH logins, and `sudo` activity.
* `syslog`: Centralized system event logs.
* `journalctl`: Query logs generated by `systemd` services (`journalctl -u ssh`).
* `tail -f /var/log/auth.log`: Monitor authentication logs in real time.
